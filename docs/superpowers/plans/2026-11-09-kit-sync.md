# Kit sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make appliance-ui drift visible (one status command), cheap to fix (sync PRs) and safe to skip (release notes with a skip rule), and run the check in the consumers' deploy preflights and CI.

**Architecture:** Small pure modules in `scripts/lib/` (version compare, changelog parse, copy classification) with thin CLIs in `scripts/` (`drift.mjs`, and `--pr` on `sync.mjs`). Consumer state is read from GitHub main through an injected `fetchFile`, so tests need no network. The existing copy model, `VERSION` checksums and `verify.mjs` / `verify.py` stay unchanged.

**Tech Stack:** Node 22 ESM, `node:test`, `gh` CLI (already logged in), `wt` for worktrees. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-09-kit-sync-design.md` (PR #25; read it first). Parts 1–4 of the spec are this plan. Part 5, the "what's live" view, gets its own design and plan and is **not** built here.

## Global Constraints

- Node `>=22` (`engines` in `package.json`); no new dependencies.
- Keep the kit's public files, HTML IDs and class names unchanged; `sync.mjs` keeps refusing to replace a newer copy (exit 2).
- `tokens.json` `version` and each consumer's `VERSION` are the only version records; no second source of truth.
- A drift check never blocks a deploy because the network is down: an unreachable consumer is "unknown", exit 0.
- Exit non-zero only for: a modified copy, a missing or malformed `VERSION`, or a copy behind across a release marked "needs a consumer change". Everything else exits 0.
- Sync PRs are opened, never merged, never pushed to main; they are created in a worktree from `wt new <repo> <branch>`, based on main, never stacked.
- LocalAI's PC checkout (`C:\LocalAI\repo`) is never edited. Consumer PRs are merged only on the owner's "merge".
- Read consumers from GitHub main with `gh` or `git`, not the GitHub MCP server (it fails to connect).

## Review Focus

- Version compare is numeric per part: `2.10.0` is newer than `2.9.0` (a string compare gets this wrong).
- Consumer repo unreachable or offline: report "unknown", exit 0, never throw.
- `VERSION` missing, empty or not JSON: "unknown copy", exit 1, no crash.
- Copy newer than the kit's main (the smart display was at 2.11.0 against a stale 2.9.0): "ahead", exit 0.
- `VERSION` lists a file the consumer no longer has: counted as modified.
- A release in the gap with no changelog entry: "unclassified", exit 0, line still printed.

### Task 3: Classify a copy

**Files:**
- Create: `scripts/lib/drift.mjs`
- Test: `tests/drift.test.mjs`

**Interfaces:**
- Consumes: `compareVersions`, `releasesBetween`, `parseChangelog`.
- Produces: `classifyCopy(input: {copyVersion: string | null, kitVersion: string, modified: string[], unreachable: boolean}, log: Map): {state: 'current' | 'behind-skippable' | 'behind-needs-change' | 'ahead' | 'modified' | 'unknown-copy' | 'unclassified' | 'unreachable', exit: 0 | 1, line: string}`.
- Rules: unreachable → `unreachable`, 0; `copyVersion` null → `unknown-copy`, 1; `modified` non-empty → `modified`, 1 (checked before version state); equal → `current`; newer → `ahead`, 0; behind with any in-range release `skip: false` → `behind-needs-change`, 1 and the line names that release's note; behind with any `skip: null` and none `false` → `unclassified`, 0; otherwise `behind-skippable`, 0.

- [ ] **Step 1: Write the failing table test**, one row per state above, asserting `state`, `exit` and that `line` contains both versions (and the file names for `modified`, the note for `behind-needs-change`).
- [ ] **Step 2: Run** `node --test tests/drift.test.mjs`; expected FAIL.
- [ ] **Step 3: Implement** `classifyCopy` as a pure function, no I/O.
- [ ] **Step 4: Run** the test; expected PASS. Commit `feat: classify a kit copy against the kit`.

### Task 4: The drift command

**Files:**
- Create: `consumers.json`, `scripts/drift.mjs`, `scripts/lib/consumers.mjs`
- Modify: `package.json` (script `"drift": "node scripts/drift.mjs"`)
- Test: `tests/drift-cli.test.mjs`

**Interfaces:**
- `consumers.json`: array of `{name, repo, folder, check}` with `repo` as `azmusgb/<name>`; entries for `pi-hub` (`hub/static/ui`), `LocalAI` (`app/public/ui`), `bambuhelper-smart-display` (`assets/ui`). `check` is the narrowest command for that consumer (used by Task 5): pi-hub `python3 -I hub/static/ui/verify.py hub/static/ui`; LocalAI `node app/public/ui/verify.mjs app/public/ui`; smart display `node assets/ui/verify.mjs assets/ui` or `null` when it can't run on the Mac (confirm in that repo's `.github/workflows/validate.yml`).
- Produces in `consumers.mjs`: `readConsumer(c: {repo, folder}, fetchFile: (repo, path) => Promise<Buffer | null>): Promise<{copyVersion: string | null, modified: string[], unreachable: boolean}>`. It fetches `<folder>/VERSION`, then each file in its `files`, and lists names whose SHA-256 differs or is missing (checked against the consumer's own `VERSION`, since the kit has no per-release checksums). `fetchFile` throwing or returning `undefined` for `VERSION` means unreachable; `null` means the file does not exist.
- `drift.mjs` default `fetchFile` uses `gh api -H "Accept: application/vnd.github.raw" repos/<repo>/contents/<path>` and returns `null` on a 404. It prints one line per consumer from `classifyCopy`, then exits with the highest `exit` value. Export `main(argv, {fetchFile, log})` so tests inject a stub.

- [ ] **Step 1: Write the failing tests** with a stub `fetchFile` over an in-memory repo map: a clean consumer prints `current`, exit 0; one file changed prints `modified` and the file name, exit 1; a consumer whose `fetchFile` throws prints `unreachable`, exit 0; `VERSION` containing `not json` prints `unknown-copy`, exit 1; a `VERSION` listing a file the stub lacks counts as modified.
- [ ] **Step 2: Run** `node --test tests/drift-cli.test.mjs`; expected FAIL.
- [ ] **Step 3: Implement** `readConsumer` and `drift.mjs`.
- [ ] **Step 4: Run** `node --test tests/` then `npm run drift`; expected: tests PASS, and the command prints three real lines (pi-hub 2.9.0, LocalAI 2.7.0, smart display 2.11.0 behind 2.15.0 as of this plan) with a non-zero exit only if the changelog marks a skipped release as needs-change. Paste that output in the PR.
- [ ] **Step 5: Commit** `feat: npm run drift lists each consumer's kit version`.

### Task 5: Sync PRs

**Files:**
- Modify: `scripts/sync.mjs` (add `--pr` and `--dry-run`)
- Create: `scripts/lib/sync-pr.mjs`
- Test: `tests/sync-pr.test.mjs`

**Interfaces:**
- Consumes: `releasesBetween`, `parseChangelog`, `consumers.json`.
- Produces in `sync-pr.mjs`: `buildPrBody(input: {name: string, from: string, to: string, entries: {version, skip, note}[]}): string` (a heading, one bullet per release marked skippable or needs-change with its note, and a line `Check: not run on the Mac` when the consumer's `check` is null); `planSync(c: {name, repo, folder, check}, from: string, to: string): {branch: string, steps: string[]}` with `branch` = `kit-sync-<to>` and `steps` the ordered commands (`wt new`, sync into the printed path, run `check`, commit, push, `gh pr create --base main`). The commit message ends with the Co-Authored-By line and the PR body with the Generated-with line from the session's attribution rules.
- `sync.mjs <repo> --dir <folder> --pr` runs those steps; `--dry-run` prints them and runs nothing. It stops without opening a PR if the consumer's check fails, or if the copy is newer (exit 2, as today).
