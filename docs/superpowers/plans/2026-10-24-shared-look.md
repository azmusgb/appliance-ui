# One Shared Look Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `appliance-ui` (tokens, shared components, `<appliance-header>`, sync and drift check) and adopt it in Local AI, Pi Hub, Materials and Workshop OS so the four apps and the display look like one appliance.

**Architecture:** `appliance-ui/tokens.json` and `suite.json` are the source of truth; `scripts/build.mjs` generates `dist/` (CSS, the header web component, a C header); `scripts/sync.mjs` copies `dist/` into each app with a checksummed `VERSION`; each app's tests run `check/verify.*`. Apps alias their existing CSS variable names to `--ui-*`.

**Tech Stack:** Node ≥ 22 (no runtime deps; Playwright as a dev dependency for header tests), vanilla Web Components, CSS custom properties, Python 3 stdlib (Pi Hub check), C header for ESP32 (Workshop OS).

**Spec:** `docs/superpowers/specs/2026-10-24-shared-look-design.md`

## Global Constraints

- Look "Slate + Sky": dark default; light via `prefers-color-scheme: light` unless `[data-theme="dark"]`; `[data-theme="light"]` forces light.
- Header names and order: Home · Assistant · Workshop · Materials; `app` ids `home`, `assistant`, `workshop`, `materials`.
- Header height 48 px (≥ 720 px wide), 44 px below; exposed as `--ui-header-h`.
- Links: home `http://10.0.0.30/` | `http://pi.tailfa018e.ts.net/`; assistant `https://10.0.0.21/` | `https://bill-hpdesktop.tailfa018e.ts.net/`; workshop `http://10.0.0.124/` | none; materials `https://filamentinventory.netlify.app/` (both).
- Tailscale set when the page host ends `.ts.net` or is in `100.64.0.0/10`; the current app links to `/`.
- Contrast: WCAG AA, 4.5:1 body text, 3:1 large text and icons, both modes; the build fails below it.
- Size: header JS + `tokens.css` + `components.css` ≤ 12 KB gzipped; else Workshop portal uses `appliance-header.lite.js`.
- The header makes no network requests.
- `appliance-ui` has no runtime dependencies; generated files carry a "generated by appliance-ui vX.Y.Z — do not edit" banner.
- Each app keeps its own CSS names as aliases of `--ui-*`; no page layouts, routes or features change.
- Every repo ships through its own process: Local AI via `npm run ship -- <PR>`; Pi Hub via `deploy/install.sh`; Materials via its PR CI + Netlify; Workshop OS via its single active firmware candidate PR and physical acceptance.

## Review Focus

1. **A `100.x` address outside `100.64.0.0/10`, or a bare hostname like `pi`** → home-network links (test in Task 3).
2. **An app that sets `data-theme` itself** (Pi Hub's theme toggle) → the header follows the page's theme, not the device's (test in Task 3).
3. **A PWA in standalone mode on a notched iPhone** (`black-translucent` status bar, Local AI) → the header clears `env(safe-area-inset-top)` and nothing sits under the clock (test in Task 3; checked in Task 5).
4. **An app's existing sticky/fixed top bar** → it sits below the header (`top: var(--ui-header-h)`), never under it (checks in Tasks 5 and 7).
5. **A service worker serving the old shell after the update** → each app bumps its shell cache and lists `ui/*` files, so one reload shows the new header (tests in Tasks 5, 7, 8).
